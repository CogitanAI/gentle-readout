PROVENANCE NOTE — READ BEFORE REPRODUCING
-----------------------------------------
`round10_stageA.py` sweeps R_GRID = (0.75, 0.85, 1.0, 1.18, 1.35) in one
process.  On the reference machine that run completes the first three points
and then dies inside SuperLU's allocator on the fourth factorization:

    RuntimeError: SUPERLU_MALLOC fails for buf in intCalloc()
    at line 173 in file .../SuperLU/SRC/memory.c

This is a genuine memory limit, not a numerical failure.  r > 1 squeezes the
q-quadrature into tighter combs, so the codewords need more Fock space; at
fixed N = 84 the sparse shift-invert (`eigs(..., sigma=-1e-9)` -> `splu`) in
`perception_step3.induced_rates` exceeds what SuperLU can allocate once three
prior factorizations have fragmented the heap.  Each process holds ~2 GB.

The r > 1 points DO complete in a fresh process.  They were obtained with
`one_r.py <r>`, which imports `round10_stageA` and calls `score(N, D, r)`
unchanged — same constants, same code path, no numerical modification.  Only
the heap differs.

A reproducer with more memory should get all five from the single sweep.  If
the sweep dies at r = 1.18, run the last two points individually.
